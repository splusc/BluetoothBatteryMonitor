# 开机自动启动选项设计

## 目标

在 TrayMonitor 的托盘右键菜单中增加“开机自动启动”复选项。该功能仅作用于当前 Windows 用户，默认关闭，不需要管理员权限。

## 实现方式

使用 Windows 当前用户注册表启动项：

`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`

启用时写入名为 `TrayMonitor` 的字符串值，内容为带引号的当前可执行文件完整路径。禁用时删除该值。注册表是此选项的唯一状态来源，不将状态重复保存到 `settings.json`。

采用注册表而不是启动文件夹快捷方式或任务计划程序，因为它是当前用户应用最小且原生的启动机制，不需要新增依赖、快捷方式生成逻辑或管理员权限。

## 菜单行为

- 在“立即刷新”之前增加“开机自动启动”复选项。
- 每次打开菜单时读取注册表；仅当值与当前 EXE 的带引号路径匹配时显示为已启用。
- 勾选后写入当前运行的 EXE 路径；即使 EXE 被移动，用户再次勾选也会刷新路径。
- 取消勾选后删除 `TrayMonitor` 启动项；启动项不存在时视为成功。
- 修改失败时显示简短错误提示，并将菜单恢复为注册表实际状态。

## 边界与错误处理

- 只修改当前用户下名为 `TrayMonitor` 的启动项，不读取或修改其他应用的启动项。
- 路径使用双引号包裹，支持包含空格的发布目录。
- 无法取得当前进程路径或注册表访问失败时，不改变现有启动项。
- 保留现有单实例互斥锁，避免登录启动与用户手动启动产生多个托盘实例。

## 验证

- 自动检查使用当前用户下的隔离临时注册表路径，验证启用、状态查询、路径引号和禁用。
- Release 构建必须保持零警告、零错误。
- 重新发布 `win-x64` 自包含单文件。

## 非目标

- 不支持所有用户范围的启动项。
- 不创建安装器、快捷方式或计划任务。
- 不提供延迟启动、管理员权限启动或登录前启动。
